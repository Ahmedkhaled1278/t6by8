# تقرير تنفيذ Nour Social Platform — 0.26.5

## 1) مراجعة الأمان والخصوصية — تعديلات مصدرية

- إضافة تحديد محاولات لمسار إعادة تعيين كلمة المرور (8 محاولات لكل عنوان IP خلال 15 دقيقة)، وطلب إعادة إرسال تأكيد البريد (3/15 دقيقة)، والتحقق من رمز تأكيد البريد (10/15 دقيقة).
- رفض `CORS_REFLECT=1` في الإنتاج، واشتراط `WEB_ORIGIN` صريح، والتحقق من أن نطاقات الويب الإنتاجية HTTPS ومن دون مسارات.
- منع تشغيل خدمة الوسائط في الإنتاج من دون `S3_ENDPOINT` و`S3_BUCKET` وبيانات دخول صريحة، واشتراط HTTPS لنقطة S3.
- منع تشغيل API في الإنتاج من دون SMTP؛ وإلا ستبدو بعض تدفقات البريد وكأنها اكتملت بينما لا يمكن إرسال الرسائل.
- تحديث إصدار `/api/health` إلى `0.26.5` وتوثيق متطلبات الإنتاج.

هذه التعديلات لم تُثبت بعد باختبارات تكامل أو تشغيل حقيقية.

## 2) اختبار البناء والتشغيل

نجح:
- `node scripts_verify_foundation.mjs`
- `node scripts_check_ids.mjs` — 14 ملفًا و173 معرّفًا حرفيًا مفحوصًا.
- `node scripts_check_security_config.mjs` — 9 فحوص مصدرية.
- فحص JSON وسلامة syntax لملفات JavaScript الخاصة بالمشروع.

تمت محاولة فحص TypeScript للواجهة والخادم (`tsc --noEmit -p apps/web/tsconfig.json` و`tsc --noEmit -p apps/api/tsconfig.json`) لكنهما تعثرا بسبب غياب الاعتماديات وملفات أنواعها (مثل `react` و`@nestjs/common` و`@prisma/client` و`@types/node`)، وليس ذلك اختبارًا صالحًا للحكم على صحة المشروع بعد تثبيت الاعتماديات.

تعذر تثبيت الاعتماديات: فشل `corepack pnpm install --offline --ignore-scripts` عند محاولة تنزيل pnpm 10.12.1 من registry.npmjs.org بسبب `EAI_AGAIN`/تعذر DNS. لم تُشغّل اختبارات Next.js/NestJS/قاعدة البيانات أو E2E.

## 3) النشر

تم تجهيز إرشادات ومتغيرات الإنتاج في `DEPLOYMENT_PLAN_AR.md` و`.env.example` فقط. لم تُنشأ حسابات استضافة ولم تُضبط أسرار فعلية ولم يُنشر API أو الواجهة أو PostgreSQL.

## 4) APK

لا يوجد مجلد `android/` في الحزمة ولا يوجد APK مبني. يوجد Workflow في GitHub Actions يستطيع إنشاء مشروع Android وتجميع Debug APK بعد توفير رابط واجهة HTTPS منشور وتشغيل Workflow في مستودع متصل بالإنترنت. لم يُشغّل Workflow ولم يُختبر تثبيت على هاتف.

## 5) Firebase Cloud Messaging

لم يبدأ تكامل FCM؛ الترتيب المعتمد يضعه بعد نشر الخدمات وبناء APK واختباره. الموجود حاليًا هو Web Push عبر VAPID وليس دليلًا على أن FCM الأصلي للهاتف مفعّل.

## الملفات اللازمة للخطوات المتبقية

- مستودع GitHub المتصل بالنسخة الحالية.
- عناوين HTTPS النهائية للواجهة وAPI.
- قيم أسرار الاستضافة وPostgreSQL وS3 وSMTP من المستخدم/مزود الخدمة، ولا تضعها في المستودع.
- إعداد مشروع Firebase وملف/إعداد Android الصحيح بعد تجهيز مشروع Android.
