# سجل الإصدار 0.3.0 — مرحلة الحسابات والجلسات

## ما أُضيف
- إنشاء حساب باسم مستخدم وبريد إلكتروني واسم ظاهر وكلمة مرور.
- تسجيل الدخول وإنشاء جلسة عشوائية عالية العشوائية؛ لا يُخزَّن رمز الجلسة الخام في قاعدة البيانات بل بصمة SHA-256.
- تخزين كلمات المرور باستخدام scrypt وملح عشوائي، ومقارنة الناتج بطريقة ثابتة الزمن.
- Cookie للجلسة بخيارات HttpOnly وSameSite=Strict وSecure في بيئة الإنتاج.
- قراءة الحساب الحالي، عرض الجلسات النشطة، إنهاء جلسة محددة، وتسجيل الخروج من الجلسة الحالية أو جميع الجلسات.
- جدول AuthSession مرتبط بالحساب ويُلغى تلقائيًا عند حذف الحساب.
- إبقاء email وpasswordHash اختياريين في المخطط لتجنب فرض قيم على حسابات قديمة عند ترقية قاعدة بيانات موجودة؛ لا يمكن للحساب القديم تسجيل الدخول قبل استكمال بياناته بطريقة آمنة.

## المسارات
- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/auth/me`
- `GET /api/auth/sessions`
- `POST /api/auth/sessions/revoke` مع `sessionId`
- `POST /api/auth/logout` مع `allSessions: true` لإنهاء كل الجلسات

## حدود مهمة
- هذه مرحلة أساس للمصادقة وليست إعلانًا أن المنصة جاهزة للإطلاق العام.
- يلزم قبل الإنتاج إضافة تحديد معدل محاولات تسجيل الدخول، والتحقق من CSRF/أصل الطلبات حسب النشر، وسياسة استعادة الحساب والتحقق من البريد، وإجراءات ترحيل قاعدة البيانات الرسمية، واختبارات تكامل فعلية.
- واجهة الموقع الحالية لا تتضمن بعد نماذج التسجيل والدخول أو ربط الجلسة بها.
- لا يمكن اعتبار المصادقة مُختبرة تشغيلًا قبل تثبيت الاعتماديات وتشغيل Prisma وقاعدة PostgreSQL وإجراء اختبارات HTTP فعلية.
